# who-finder

Agent skill + CLI: **deep public research on people or companies**. Creators are one scenario, not the product.

Give it a brief in plain English. It works out what kind of search that is, plans the queries itself, pulls public profiles, scores every result against your ICP with attributed reasons, ranks by priority, and remembers who it already showed you so outreach never gets the same name twice.

Python 3.11+. No pip, no build step. One dependency: a [ScrapeCreators](https://scrapecreators.com) API key.

  search snippet, not the profile.

      why   topic match: ai video (+18) · match 'head of' (+12) · audience 24k in
            target band (+20) · geo match (+8)

      tags  hiring, masked-profile

      url   https://www.youtube.com/@adlab

Everything above is generated by the engine. The agent pastes it — it does not write the analysis, so it cannot invent a finding the data does not support.

## Reports you can forward

The terminal output is for you. Add `--format` and the same run writes a document for everyone else.

```bash
who-finder find "people building AI video tools" --deep 10 \
  --format md,pdf --out ~/Desktop/shortlist
```

A cover, a summary of the landscape, a ranked table, then a full page on each person — role, audience, the arithmetic behind their fit score, what is missing from it, recent activity, and the exact queries that found them — followed by a method section listing every search that ran and every source that came back empty.

Four formats: `md` for pasting anywhere, `html` for the best-looking version, `pdf` for attaching, `json` for building on. Comma-separate to write several from one build so they can never disagree.

**The PDF needs nothing installed.** No WeasyPrint, no wkhtmltopdf, no headless Chrome — it is written directly against the fourteen base fonts every reader already has, so it works on a laptop, a server, or a CI runner with nothing but Python. For a prettier document, open the HTML and print it from a browser.

Asking for "ten more" does not re-run the search. Discovery already found more names than `--deep` paid to enrich, so `more --offset 10` continues down the stored ranking at one credit per profile, and `report --offset 10` re-cuts a slice you already own for free. See [reference/reports.md](reference/reports.md).

## Searching the same question several ways

One phrasing only finds the people who describe themselves that way. So `find` reframes the topic before it searches: exactly as asked, as a quoted phrase, and with the leading qualifier dropped — that last one reaches people doing the work who never adopted the buzzword.

What the engine will not do is guess at a field's vocabulary, because a synonym list good enough for one domain is wrong for every other. Supply those yourself:

```bash
who-finder find "people building text-to-video tools" --deep 10 \
  --frame "generative video" --frame "AI film production"
```

Each extra framing is one more search, not a whole new angle set — three frames on a five-angle scenario costs seven credits rather than fifteen. Every result records which query found it, and anyone surfaced by more than one framing is flagged as corroborated, which is usually the strongest signal in a shortlist. See [reference/framing.md](reference/framing.md).

## Install

```bash
git clone https://github.com/romaluev/who-finder ~/.cursor/skills/who-finder
python3 ~/.cursor/skills/who-finder/scripts/who_finder.py
```

That second line is safe to run before anything is configured — it prints what the tool
does, whether your setup is ready, and the one command worth trying first. There is no
install step, no `pip`, and no config file: **clone and run**.

Use `~/.claude/skills/who-finder` for Claude, or `.claude/skills/who-finder` inside a project to scope it to one repo. Any folder your agent loads skills from works — the skill resolves its own path.

**Python:** works on 3.9 and up, standard library only. That includes the Python
already on macOS, so most people need to install nothing at all.

### Try it before you have a key

```bash
python3 .../who_finder.py find "founders of AI video tools" --deep 10 --dry-run
```

No key, no network, no spend. It prints the exact searches it would run and what they
would cost. This is the honest way to see how the tool behaves before committing to it.

### Then get a key

The one thing you cannot skip: a [ScrapeCreators](https://scrapecreators.com) API key.
Credits are billed per key, so everyone uses their own.

```bash
export SCRAPECREATORS_API_KEY=...
python3 .../who_finder.py doctor
```

`doctor` reports one of four states — `ready`, `skipped-unconfigured`, `auth-failed`,
`error` — in plain language, with the fix for whichever one you are in. Add `--probe` to
spend one credit on a real search and confirm the whole path works end to end.

### If you get stuck

Every wrong turn points somewhere useful rather than printing a usage wall. Typing a
search instead of a command suggests the right command; a mistyped command points at
`which`, which maps a plain-English description to the thing you meant:

```bash
python3 .../who_finder.py which "how much will this cost"
python3 .../who_finder.py help
```

### Verification status — read this once

The parsers here were written against ScrapeCreators' **documented** response shapes and are covered by 115 offline tests. They have **not** been exercised against a live API key. Run `doctor --probe` as your first command.

If upstream has moved a field since, you will not get a silent empty result: any source that answers in a shape the parsers cannot read is reported as `UNPARSED` with a `SCHEMA DRIFT` line naming the source and the new key path. Zero rows under that banner is a parser bug, not an empty market. Send that line along in a bug report and the fix is usually one key.

## Teach it your ICP

Fit scoring is a local JSON file you own. Without one, the engine derives a topic gate from your brief and applies generic seniority rules.

```bash
python3 scripts/who_finder.py icp init      # editable template
python3 scripts/who_finder.py signals       # signal names you can score
```

```json
{
  "must_any": ["ai video", "generative video"],
  "boost": { "founder": 15, "head of": 12, "agency": 10 },
  "penalty": { "student": -20, "intern": -15 },
  "audience": { "min": 1000, "sweet_min": 10000, "sweet_max": 2000000, "weight": 20 },
  "geo": { "prefer": ["united states"], "weight": 8 },
  "signals": { "hiring": 10, "funded": 12 }
}
```

If results feel off, edit this file. That is the intended control surface — the scoring stays inspectable instead of drifting into model taste.

Two worked examples ship in `assets/`, ported from a real GTM rubric: [`icp.higgsfield-accounts.json`](assets/icp.higgsfield-accounts.json) scores companies on headcount, category and friction, and [`icp.higgsfield-operators.json`](assets/icp.higgsfield-operators.json) scores the people inside them on title and function. Use them as a starting shape:

```bash
python3 scripts/who_finder.py find "NA agencies scaling AI video" \
  --deep 10 --icp assets/icp.higgsfield-accounts.json
```

[reference/icp.md](reference/icp.md) walks through what does and does not survive that kind of translation.

## CLI

```bash
B="python3 scripts/who_finder.py"

$B doctor --agent                                  # health + credits
$B which "who should we pitch" --agent             # phrase -> command
$B find "founders of AI video tools" --deep 10     # the main verb
$B find "AI video ads" --scenario creators --deep 10
$B find "AI video ads" --frame "generative creative" --deep 10
$B find "AI video ads" --deep 10 --format md,pdf --out ~/Desktop/shortlist
$B report --status new                             # re-render the brief, 0 credits
$B report --limit 10 --offset 10 --format html --out next   # page a slice you own, 0 credits
$B more --offset 10 --limit 10                     # the next ten, enrichment only
$B enrich person/linkedin/jane-doe                 # dossier for one name
$B expand company/linkedin/acme                    # its staff + lookalikes, 0 credits
$B show person/youtube/adlab                       # full dossier card
$B mark person/linkedin/jane-doe --status outreached
$B export --status new --band strong --out handoff.csv
$B import known-customers.csv                      # seed a skip list
```

Add `--agent` to any command for JSON.

### Built for agents

| flag | why it matters |
|---|---|
| `--agent` | one JSON envelope on stdout: `{meta, plan, table, results}` |
| `--dry-run` | exact queries + credit ceiling, zero spend, no key needed |
| `--max-credits N` | refuse (exit 8) before the first request if the plan costs more |
| `--select PATHS` | keep only the fields you will read; `meta` and `error` always survive |
| `--deliver SINK` | `stdout` \| `file:<path>` \| `webhook:<url>`, atomic file writes |
| `--profile NAME` | saved flag sets for repeat runs; explicit flags still win |

```bash
$B agent-context --agent    # the whole CLI described from live constants
$B which "how much will this cost" --agent
$B find "..." --deep 10 --agent --select results.n_new,results.entities.id,results.entities.priority
$B profile save nightly --set deep=10 --set scenario=people
$B --profile nightly find "AI video ops hires" --agent
```

Every failure is branchable rather than a stack trace:

```json
{"meta":{"ok":false},"error":{"code":8,"name":"budget refused — ...",
 "message":"plan needs up to 25 credits, --max-credits is 6",
 "fix":"raise --max-credits, lower --deep, or narrow --sources"}}
```

`0` success · `2` usage · `3` not found · `4` auth · `5` upstream · `8` budget · `9` delivery · `10` config

### Cost

| call | credits |
|---|---|
| each query angle in a plan | 1 |
| each enriched entity (`--deep N`) | 1, or 0 on a YouTube/TikTok cache hit |
| `report`, `expand`, `show`, `export`, `mark`, `import` | 0 |

`find "brief" --deep 10` typically costs ~15 credits. Bare `find` costs one per angle and returns names only.

**See the bill before you pay it.** `--dry-run` prints the exact queries the planner built and the credit ceiling, without touching the network or needing a key:

```bash
$B find "AI video tooling" --deep 25 --dry-run
```
```
PLANNED QUERIES (5)
  1. linkedin_people     li-in
     q: site:linkedin.com/in ai video tooling
  ...
COST CEILING
  discovery        5 credits (1 per query above)
  enrichment  <=  25 credits (1 per profile, 0 on a cache hit)
  total       <=  30 credits
```

`--max-credits N` turns that ceiling into a hard stop: the run exits 8 before the first request rather than overspending.

## Where the data lives

`.who-finder/roster.sqlite` in your working directory: entities, hits, dossiers, ICP scores and score history over time. Override with `WHO_FINDER_HOME` or `--db`. Two people can share a roster by pointing `--db` at the same file.

A name stays `new` until *you* mark it. Re-running the same search does not quietly retire it into "known" — the outreach queue is only cleared by an actual decision.

## What it does not do

Send messages. Log into LinkedIn or use cookies, Sales Navigator, or a member session — LinkedIn here is Google-indexed public URLs plus vendor profile endpoints. Act as a CRM. Print a job title it did not receive.
