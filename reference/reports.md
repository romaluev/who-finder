# Reports

The terminal brief is for the person running the command. A report is for everyone else — the colleague who will do the outreach, the client who asked what the market looks like, the folder this gets filed in six months from now. It is the same data with the context a reader needs when they were not there when it ran.

## Producing one

`--format` turns any command that ranks people into a document writer.

```bash
who-finder find "people building AI video tools" --deep 10 \
  --format md,pdf --out ~/Desktop/shortlist

who-finder report --limit 10 --format html --out ~/Desktop/shortlist
who-finder more --offset 10 --limit 10 --format md --out ~/Desktop/next-ten
```

`--out` is a path **without** an extension; each format appends its own. Comma-separate formats to write several at once — they are rendered from a single build, so the PDF can never describe a different shortlist than the Markdown beside it. Default is `text`, the terminal brief.

## The four formats

| format | what it is for |
|---|---|
| `md` | pasting into Notion, Slack, a doc, or a pull request. Plain CommonMark with tables. |
| `html` | the best-looking one. A single self-contained file — no fonts, scripts, or images are fetched — that opens anywhere and prints to an excellent PDF. |
| `pdf` | attaching to an email without needing a browser. Generated by a small typesetter in the standard library. |
| `json` | the document model itself, for anyone building something else on top. |

### Why there are two paths to a PDF

The tool's promise is clone-and-run: no `pip install`, no build step, nothing to configure. Every good HTML-to-PDF engine breaks that promise. WeasyPrint and wkhtmltopdf need installing, and headless Chrome needs Chrome, which is not on every machine and is not on any CI runner by default.

So `pdf` is written directly, using only `zlib` and the fourteen base fonts every PDF reader is required to have. It handles pagination, real Helvetica metrics for line breaking, rules, colour, and key/value layout. It does not do images, columns, or ligatures, and it never will.

If you want the prettier document, generate `html` and print it from a browser. That path has CSS, web-quality typography, and proper page rules, and it costs nothing extra because the HTML is already written.

## What is in the document

**Cover.** The brief, which slice of the ranking this covers, the fit rules in force, how many names were new, and what it cost.

**Summary.** The findings the engine synthesised, then **Easy to miss** (the cross-set notices a ranking table hides), an at-a-glance block, the ranked table, recurring themes, and what the report does *not* cover.

**The people.** One entry each, in priority order: who they are, why they fit, why reach out, how to reach them (only addresses they published), what they have been saying, company and colleagues, similar profiles, and — when the data supports it — an **Easy to miss** line (same person on another platform, creator-shaped audience, a Calendly, a masked title).

**How this was researched.** Every framing used and why, every query run, per-source coverage, and how to read the fit score. This section is why the report can be forwarded to someone who was not there: it says what was asked and what was not, so nobody mistakes a gap in coverage for a finding.

## Reading two things carefully

**"Found by"** lists the queries that surfaced that person. With several framings in flight this is the most interesting line on the entry, because it tells you whether someone is genuinely central to the topic or turned up on one narrow phrasing.

**"Corroboration"** appears when more than one framing found the same person. Independent phrasings converging is evidence the fit score cannot see, since the score only reads the profile and knows nothing about how the profile was reached.

## Pagination

`--limit` is how many people get a full entry. `--offset` skips that many from the top of the ranking, and entries keep their true rank — a report at `--offset 10` starts at "11.", not "1.", so two reports can sit side by side without colliding.

Discovery returns far more names than `--deep` pays to enrich, so there is almost always more ranking below the last report:

- `report --limit 10 --offset 10` re-cuts people already enriched. **Zero credits.**
- `more --offset 10 --limit 10` continues down the ranking and enriches whatever has not been enriched yet. **One credit per new profile, zero for discovery.**

Neither runs a search. Re-running `find` to get more names re-buys every query and mostly returns the same people, now marked `known`.

## Safety

Names, bios and titles come from third-party profiles, so every value is HTML-escaped on the way into the HTML report — a profile cannot inject markup or script into a document you forward. In the PDF, characters outside the font's encoding are transliterated (`—` to `-`, curly quotes to straight) rather than dropped, so text never silently loses punctuation, and parentheses and backslashes are escaped so a name cannot break the content stream.
